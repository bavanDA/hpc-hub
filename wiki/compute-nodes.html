Compute nodes and queues

A compute node is a machine you borrow for a set time. HPC Hub gets one for you, tells you what each queue allows and costs, warns you about maintenance, and counts down the time left.

Getting a node#

If you turned on Get a compute node when I connect, a node comes with every connect. If not, the card says No compute node with a Get one link. Either way you can open Compute node from the card's ⋮ menu.

The window Get a node on Wulver has:

  • Size: quick sizes to start from.
  • Cores, Memory and Time. The most you can ask for comes from the queue you picked.
  • Queue and priority: see below.
  • Cost: what the node costs in SUs, when the cluster bills for it.
  • Use this size next time and Ask before each request.

Press Get node. The node is a Slurm job like any other, so it shows on the Jobs page too.

Time left#

When connected, the card shows your node and how long it has, for example On node n0123 · job 123456 · 3 h 20 min left. The time counts down while you watch.

About 15 minutes before the end, HPC Hub sends a notification: Save your work. The node ends when its time is up. When the time is up, Slurm ends the job, and everything running on that node stops, including terminals you opened there.

If the card says started elsewhere, the node came from another job you already had, for example one an agent or VS Code got earlier (the Reuse a node you already have setting).

Giving a node back#

When you are done early, open the card's ⋮ menu and choose Release node. The app asks first: anything running on it stops, but you stay connected and your files stay where they are. Disconnect releases the node too.

Quitting the app does not release your node; it keeps running until its time is up. To release everything as you leave, use Settings, Disconnect all and quit.

Queues, priorities and groups#

Queue and priority opens three choices. The lists come from Slurm, so they show only what your account can use:

  • Queue: which group of nodes and time limits the job uses. Each queue has a line saying what one job can get there, for example Up to 3 days · up to 128 cores · up to 500 GB memory, and what is easy to miss about it.
  • Priority: how the job is billed and how soon it starts.
  • Group to bill: the account the hours go to, for example mygroup. Empty means your default group.

Learn about queues, at the top of the queue list, opens the full table of limits.

What a whole-node queue means#

On some queues you always get whole nodes, even if you ask for fewer cores. The app says so in the queue's line: You always get whole nodes, even if you ask for fewer cores. On those queues the cost is counted per node, however little of it you use. Asking for 2 cores on a whole-node queue costs the same as asking for all of them, so pick such a queue when you can use the whole machine.

Some queues also say Other jobs can stop yours. Work there can be stopped to make room for other jobs, so save often or pick another queue for long runs.

The Limits tab#

Usage, Limits (also opened by Learn about queues) shows the most one job can ask for on each queue you can use, read from Slurm just now. Nothing is typed in by hand, so it matches what the cluster will accept.

ColumnWhat it says
QueueThe name, whether it is the default, how many nodes it has, whole nodes only and other jobs can stop yours where they apply. A queue that is down says so.
Longest timeThe longest a job may run, and the time you get if you don't ask.
NodesThe most nodes one job may use.
CoresThe most cores one job may use, and how many each node has.
Memory per nodeThe memory limit, and the memory per core where the queue sets one.
GPUs per nodeShown when the cluster has GPUs: how many and of which kind.
Cost an hourIn SUs per core, per GPU or per node, or Free.

If some queues need a group or priority you don't have, the note above the table says how many. Under it, Priorities lists each priority with its longest time, its caps for One job and for All your jobs together, and what it does to the SUs (Free, Normal or, for example, 2x). A job runs under one priority, which can set a shorter time or a lower cap than its queue.

The maintenance warning#

Clusters book maintenance ahead of time. Slurm won't start a job that would still be running when maintenance begins, so a long job asked for the day before maintenance just waits.

When you ask for a node, HPC Hub reads the booked maintenance from Slurm. If the time you asked for runs into it, the node window says so before you send the request, for example:

Maintenance starts Tue, Nov 10 at 7:50 AM EST. A 12 h job can't finish before then, so it would wait until maintenance is over. Shortened, it can start now.

You choose:

  • Shorten to a time that ends before maintenance, with a few minutes to spare, or
  • Keep your time and wait.

Nothing changes unless you press Shorten. While maintenance is under way, the window says Maintenance is under way. New jobs wait until it is over. Only maintenance of the whole cluster counts; a few nodes taken out for repairs don't hold up your job.

On the Jobs page, a job held back this way shows Waiting: maintenance has to finish first.
