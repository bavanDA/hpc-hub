Projects and moving between clusters

A project is a named folder on a cluster. Open it in your tools in one click, and copy or sync it to another cluster together with its Claude chats.

Make or add a project#

On the Projects page:

  • New project makes a new folder: a Name (like thesis), the Cluster, what to Start with (Empty, LaTeX paper or Python), whether to Make it a git repository, and where to make it.
  • Add folder turns a folder you already have into a project.

The list shows each project's folder, cluster, group, when you last opened it, what is running in it and its git branch. The ⋮ menu has Edit, Copy path and Remove from the list. Removing only takes it off the list; the folder on the cluster stays.

Scratch gets cleaned up. Keep work you need in your project space. See Backup of scratch.

Open a project#

Open connects to the cluster if needed and offers: Code, Files, Terminal, VS Code, and under Agents, Claude, ChatGPT, Antigravity, Cursor and Ask all agents. With Papers turned on there is also LaTeX. Each one starts in the project's folder.

Copy or sync to another cluster#

Moving to a new cluster, or keeping a copy of your work on two? Copy or sync on a project does it in one window:

  1. Where: the cluster and the folder to put it in. The app suggests your project space there.
  2. How:
    • Globus: cluster to cluster, for big projects. Copying again only sends what changed, so it works as a sync. Globus has to be set up first (Files, Transfers).
    • Through this laptop: simple, fine for smaller projects.
  3. What to take: the app measures the project's parts. Untick what stays behind, such as large outputs you can make again.
  4. Claude chats: tick the chats to keep going there. They move with the project, so you can continue them on the new cluster.

Press Copy or Sync, with the size on the button. Both clusters must be connected. Progress shows under Copies on the Projects page, where Stop copy can stop it.

Copying to another folder on the same cluster works too. The cluster copies it itself, on your compute node, and copying again only sends what changed.
