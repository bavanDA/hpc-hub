Terminals

Every terminal in HPC Hub is a tmux session on the cluster, so it keeps running when your laptop sleeps, the Wi-Fi drops or you close the app. The timeline lets you read back and mark what matters.

Open a terminal#

Press Terminal on a cluster card, or New terminal on the Terminals page. The New terminal window asks:

  • Name: anything you like. It starts as the time, like Terminal 14:05.
  • Cluster, when more than one is connected.
  • Run on: Login node or Node n0123, your compute node.
  • Start in: the folder to start in. Empty means your home folder.

Press Open terminal.

Login node or compute node?#

The login node is shared with everyone on the cluster. It is the right place for editing files, moving them around and submitting jobs. Your compute node is yours alone, and it is the right place for builds, scripts and heavy work.

Long installs#

Installing a big package (a conda environment, a large pip install, compiling code) can take a long time and a lot of CPU. Run it on your compute node: pick Node under Run on.

A terminal on the compute node lives as long as the node does. When the node's time is up, the terminal stops with it. Before a long install, check the time left on the cluster card, and get a node with enough time if needed. See Time left.

Sessions keep running#

Each terminal runs inside tmux on the cluster. Closing a tab doesn't stop it; the app tells you Terminal 14:05 is still running. Reopen it from Sessions.

The Sessions list on the Terminals page shows every session on each connected cluster, also ones you started yourself outside the app (tmux and screen). Click one to open it again. Its ⋮ menu has Rename and Stop session; stopping asks first, because everything running in it stops.

If the cluster says tmux is not installed here, sessions can't be kept for you on it.

Reconnecting#

When the connection drops (sleep, a new network, the VPN going away), the tab says so and offers the way back:

  • Wulver disconnected. Your session should still be running there. with Reconnect to Wulver. Once the cluster is back, the tab attaches to the session again by itself.
  • You left this session. It is still running. with Attach again, when you detached from tmux yourself.
  • This session has ended. when the session is gone, for example because the shell in it exited or the compute node's time ran out. Close the tab or start a new one from the list.

The timeline#

A long build or training run prints far more than fits on the screen. The timeline is a map of the whole session, so you can find your way around it. It works on tmux sessions.

  • The map runs along the right edge of the terminal. It shows the shape of the session's output, with prompts and tables marked in color, your marks as small blue flags, and a band for the part you are looking at. Hover it to see the line number; drag it to read any part of the history.
  • Scroll up in the terminal, or drag the map, and a calm copy of the history opens over the terminal. The session underneath keeps running and nothing is sent to it.
  • Back to live, at the bottom, takes you back. It shows how many new lines came in while you were reading, like +120. Esc does the same, and so does starting to type.
  • The bar above the terminal has Previous prompt and Next prompt to jump between the commands you ran, and Previous mark and Next mark.

Marks#

A mark is a named place in the history, like a bookmark: the line where the error started, the table of results, the command that finally worked.

  1. While reading the history, click the gutter at the left of a line, or press M. A click on a table marks the whole table.
  2. Give it a name in Name this mark and press Save.

The Marks button, with the count, lists them. Click one to jump to it; each has Copy, Rename and Remove.

Marks are kept on the cluster, in your home folder, with the text of the marked lines. That means:

  • Every device signed in to the cluster sees the same marks, your phone too.
  • When tmux has trimmed old lines, or the session has ended, a mark still has its text. It shows as Saved copy, and you can read and copy it.

Terminal settings#

In Settings, under Terminals:

  • Select to copy: highlight text with the mouse to copy it.
  • Monitoring bar: CPU, memory and network of the host, under each terminal.

Pasting scripts#

A script that starts with set -e stops at the first command that fails. Pasted into a terminal, that stop is the shell itself exiting, which ends the session. Save the script to a file and run it with bash instead:

bash setup.sh
